# チャット引き継ぎチェックリスト

新規チャットを開始する前後で、最低限このチェックを実施する。
目的は「文脈喪失で品質が落ちる」ことを防ぐこと。

## 1. 開始前チェック
- [ ] `README.md` を確認
- [ ] `docs/wire.md` を確認
- [ ] `docs/core_model_architecture.md` を確認
- [ ] `docs/core_model_inventory.md` を確認
- [ ] `docs/codex_shared_context.md` の固定方針と Decision Log を確認
- [ ] 直近の `git log --oneline -n 20` を確認
- [ ] `git status` が想定通りか確認
- [ ] 作業対象ファイルの差分と未コミット変更を確認

## 2. 開始パック（新規チャット冒頭）
以下を5行程度で貼る。
- ゴール（1〜3行）
- 現在状態（この会話で観測した事実だけ。固定件数や日付つき snapshot を貼り直さない）
- 直近決定（最大5件）
- 次の作業候補（優先順 + Done条件）
- 制約（重要なものだけ）

## 3. 実装中チェック
- [ ] 変更は公開 API 経由で行う（正本直書きしない）
- [ ] Manual/Auto 優先ルールを破っていない
- [ ] DrawPath を正本扱いしていない
- [ ] Bundle 正本モデルを崩していない
- [ ] Backbone と詳細層の責務を混在させていない

## 4. テストチェック
- [ ] 変更点に対応するテストを追加/更新
- [ ] `wire_core_tests` 実行
- [ ] 異常系（失敗時の振る舞い）を最低1件確認
- [ ] テストが実装依存になっていないことを確認

## 5. 終了時チェック
- [ ] 何を変えたかを要約（ファイル単位）
- [ ] 未解決事項と次アクションを明記
- [ ] 必要なら docs 更新
- [ ] 次回に持ち越す事実は会話サマリかコミット文脈へ残し、repo 共有 docs に日付つき snapshot を増やさない
- [ ] `git status` を確認
- [ ] コミットする場合は意図が読み取れるメッセージにする

## 6. 典型的な失敗パターン
- docs を更新せず、チャットだけで合意を閉じる
- テストなしで UI 見た目だけで判断する
- 生成ロジック変更で Manual 保持を壊す
- 正本とデバッグ情報を同じ構造に混ぜる
